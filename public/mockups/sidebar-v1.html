Kept: the active-state treatment

NextRaise's active item is a solid black pill — loud. Resunova's is already an accent-tinted background with a 3px left border, the same “severity/state in form, not just a full-bleed color block” instinct used throughout this session. Copying the pill would be a downgrade; it stays as-is.

Grouped instead of flat

8 items in one list with no separation → Home/Analyze/Resume Builder ungrouped as the primary workflow, then Library (My Resumes, Cover letter, Jobs) and Coaching (Interview Prep, Advisor). Matches NextRaise's instinct to separate primary nav from secondary, using labels that reflect Resunova's actual product structure rather than a generic “Tools.”

Two-line descriptions only for the top 3

Blanket two-line treatment on all 8 items would roughly double the list's height for little gain — My Resumes and Jobs don't need explaining. Descriptions are reserved for the three entry points a new user actually has to choose between (start here / check a fit / build something), the same “hero gets the weight, everything else stays quiet” rule applied to the score tiles earlier.

The scans pill already does NextRaise's promo-card job

NextRaise uses a tinted card up top to cross-sell its Chrome extension. Resunova's gradient “3 of 5 scans remaining” pill sits in the exact same slot and already carries more urgency (a countdown, not just an ad) — left untouched rather than adding a redundant second promo surface.

Icon chips, but only where the hierarchy earns them

Rounded-square icon containers (NextRaise's treatment) went on the three hero items only, matching their bigger type. The grouped secondary items keep plain inline icons — giving every row a chip would flatten the hierarchy the grouping was just built to create.

Not done: splitting Feedback into Report Bug + Feedback

NextRaise has two separate footer buttons; Resunova's single “Feedback” already opens a dialog with a title + description field, which functionally covers a bug report too. Splitting it is a real product question (does a bug need a different intake path?), not a nav-layout fix, so it's flagged here rather than silently added.
