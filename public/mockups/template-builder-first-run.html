Template Builder — show the templates first on a cold open

Founder: “template builder should show templates first when users sign in.” Today a bare /template-builder/ drops you straight into an editor holding a demo résumé, with the template picker buried as cards inside the Style panel — so the one surface that requires no sign-up opens on someone else’s document rather than on the choice you came to make.

Any template works for any role — they differ in type and layout, not in what they can hold.

Same five templates as /templates, from the same producer (lib/templateGallery.ts), so the picker can’t drift from the public gallery. Each card leads with the role it suits and keeps the style name underneath — the vocabulary the Style panel uses, so a template you picked once stays findable.

It only appears when there is nothing to resume: no ?preset= (you already chose on the gallery), no ?builder= (opening a saved draft), no Analyze hand-off, and no meaningful saved work — reusing the store’s existing isMeaningfulResume() test. Anyone mid-document goes straight to the editor exactly as today. Picking or skipping is remembered, so it is a first run, not a toll gate.
