Decisions worth knowing before this gets built

  1. No "over limit" state, because ours is unreachable. The reference shows 4 / 1 and 3 / 2 in red. Our gate refuses the request at the limit, so you can never exceed it — drawing that state would be inventing a condition the backend makes impossible. The real states are under, at-limit, unlimited and Pro-only.
  2. One locator, one label. The reference marks an over-limit row four ways — left bar, row tint, chip and red meter. The at-limit row here keeps the tint and the words ("All used"); dropping the extra bar is the same trim the tailor rail got when three copies of one signal stopped being read.
  3. Unlimited rows are the point, not filler. On the Free plan, four of the seven things a competitor meters are uncapped here. Saying so plainly is a stronger argument than a fake gauge.
  4. The upgrade CTA uses --accent, not green. Green reads as a state we've reached; this is an action. It also only renders on a metered plan — the quota pill already has that predicate, and a Pro or admin account must never see a dead CTA.
  5. ⚠️ Interview prep is enforced in its handler, not the gate (enforced=False on both its routes). The number is real, but it comes from a different endpoint than scans — worth confirming before the row ships, or it will read a count nothing updates.
  6. ⚠️ Nothing here can be verified against a live account yet. Production is down, so these are the policy's numbers, not a round-trip.
